# 2026-07-29

## BFF Sentry observability

- Implemented the approved server-only Sentry design for Portal and Aomi
  Build on `codex/bff-sentry-observability`; no external Sentry, Vercel, or
  dashboard state was changed.
- Added private `@aomi-labs/bff-observability` with fail-closed context
  validation, Issue/Log/Ignore classification, strict event/log privacy
  scrubbers, release/environment gating, and a secret-protected staging smoke
  helper.
- Added `@sentry/nextjs@10.69.0` to both apps, preserved both Next configs,
  configured distinct `portal-bff@SHA` / `build-bff@SHA` releases and gated
  source-map uploads, and extended Build's existing Bun instrumentation.
- Wired Portal and Build ownership boundaries, removed reachable server
  console failure logging, converted downstream Rust 5xx to log-only events,
  ignored expected 4xx outcomes, and sanitized unexpected client responses.
- Patch-bumped Account to `0.1.10` for typed proxy, token, Better Auth, and
  internal observers; Deploy to `0.3.2` for preserved causes/upstream metadata;
  and Smither to `0.1.1` for artifact failure observation.
- Applied a fresh-context review pass: launch responses and telemetry now share
  one typed decision, GitHub service 401/403 handling is aligned, Build store
  failures no longer become false 404s, and sandbox artifact failures persist
  bounded cross-process codes for tree/tar/package/temp-setup/cleanup failures.
  The local artifact observer retains original exceptions but is best-effort,
  so a telemetry failure cannot change build behavior.
- Local verification: shared 41 tests; 242 Account/Deploy tests; all 88
  Smither tests; all 325 Portal tests; all 392 Build tests; package/app
  type-checks and production builds; Build lint
  and targeted Portal lint; frozen install and diff check. Full Portal lint
  retains pre-existing restricted-import/link failures.
- Restored centralized local debugging for handled failures: in development,
  the shared router prints original Issue errors/stacks and safe structured
  upstream 5xx context; ignored outcomes and production remain console-silent.
- Preserved the wallet-link signature mismatch diagnostic for local debugging:
  the wallet source supplies bounded signer/message-shape facts through the
  shared handler, which reports them only in development. The expected 401
  remains absent from Sentry and production console output, and the route no
  longer owns a direct console call.
- Simplified the app error system after architecture review. All failures now
  cross three explicit layers: source identification, one shared classifier,
  and one shared router. Portal and Build each expose only a service-bound
  `failures.handle(...)` call; their duplicated observability and launch-error
  wrappers were deleted. Deploy owns launch-domain source facts, Account owns
  proxy source facts, and the shared library owns every Issue/Log/Ignore and
  safe-response decision.
- Made that boundary explicit across every Portal device-auth catch: the
  device-auth helper now returns only typed source facts, and all six call
  points visibly invoke `portalFailures.handle(...)` instead of hiding the
  shared pipeline behind a response-producing domain wrapper.
- Removed the widget-auth operation-label normalizer while retaining the useful
  operation dimension. Every `widgetRoute` now requires an explicit canonical
  operation such as `account.read` or `wallet.rename`; no generic default or
  hidden normalization can erase or silently rewrite that context.
- Completed a repository-wide catch-boundary audit. Build and widget-auth
  response wrappers now identify source facts only, while every owning catch
  visibly calls the central router. The previously missed GitHub development
  session routes are connected, response-transform errors are local BFF
  failures, Sentry/observer failures cannot replace application responses, and
  bounded SIWE/provider debugging facts flow through the central development-
  only diagnostic path without raw credential or account identifiers.
- Re-verification after the simplification: 41 shared tests, 242 full
  Account/Deploy tests, 325 Portal tests, and 392 Build tests passed; shared,
  Account, Portal, and Build type-checks passed; Build lint passed with its
  three existing warnings. Full Portal lint remains blocked by the documented
  pre-existing restricted-import and link-rule errors.
- Remaining work is operational: create/configure `aomi-bff`, configure both
  canonical staging deployments, run and inspect both smoke events, verify
  privacy/source maps and preview silence, roll production, and update Backend
  Overview without adding notifications.
