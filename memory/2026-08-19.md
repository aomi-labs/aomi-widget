# 2026-08-19

## MCP to CLI external-signing partial execution

- Root cause: local EOA execution submitted requested calls and an appended
  service-fee call sequentially, but threw away confirmed-prefix hashes when a
  later call failed. The CLI therefore skipped its backend callback and signed
  journal update, leaving a confirmed action pending and retryable.
- Fix: `executeWalletCalls` now exposes confirmed-prefix outcomes. The CLI
  journals each confirmed staged transaction before callbacks, anchors the
  callback to the authoritative staged ID and action hash, and replays only a
  missing callback when that ID is requested again.
- Service-fee status is separate (`confirmed`, `failed`, or `not_attempted`)
  with exact amount, recipient, hash/error, and an explicit non-retryable
  recovery contract. No fee-only broadcast surface was added.
- The MCP surface remains supervisory. SIWE/OAuth and chat stage the request;
  signing and broadcasting remain local to the CLI.
- Package: `@aomi-labs/client@0.5.1`, including committed dist artifacts.
- Demo: `demo/MCP_CLI_SIGNING_DEMO.md` documents OAuth-capable and deterministic
  direct MCP flows, isolated CLI resume/signing, retry proof, and redaction.
- Live staging: session `mcp-1207e78b-fd15-4edf-9861-a04577deec0c`, staged
  `tx-1`, confirmed Base self-transfer
  `0xcefe1911f4986b941be5e6e6c5b9bef7495af4d2b51ad661204172561c3c8ef2`.
  The 12,633,000,000 wei fee hit the delegated-account in-flight limit; the
  action callback cleared pending, MCP reached `complete`, and a repeated sign
  left the wallet nonce at 7 after its single increment from 6.
- Provider errors are reduced to `details`/`shortMessage` before persistence or
  callbacks so raw signed RPC request bodies are not journaled or reported.
