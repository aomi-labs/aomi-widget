# 2026-09-01

## Wallet auth UI follow-up

- Kept live wallet connections as an explicit input to the unified Settings
  wallet model so linking cannot temporarily collapse a connected wallet into
  a linked-only row.
- Resolved numbered persisted wallet labels to colored MetaMask, Rabby,
  WalletConnect, Coinbase, Phantom, Para, and Privy marks.
- Rebuilt the initial sign-in and single-wallet finish-sign-in states around
  the Settings grouped-row design, with clear Connected, Linked, and Active
  states.
- Made connect and social-auth rows fill the popup width; live measurement on
  the local Portal confirmed 416px rows inside a 418px bordered container.
- Replaced the redundant “Not connected on this device” subtitle with an
  icon-labeled Connect action; live wallets retain the icon-labeled Disconnect
  action.
- Removed the separate Use action. A connected-but-inactive wallet now activates
  by clicking its body; only the active wallet gets the green wash and rail,
  while all connected wallets use a cooler blue status chip.
- Moved selection hover styling to the whole wallet row so it no longer ends at
  the action-column seam, and preserved durable insertion order so selecting a
  wallet never reorders the list.
- Verified 42 focused widget tests, 17 focused Portal tests, scoped ESLint,
  Portal production build, widget package build, and `npm pack --dry-run` for
  `@aomi-labs/widget-lib@2.0.8`.

## Account menu session semantics

- Replaced the raw divider beneath the account/allowance summary with a softly
  grouped header card and more deliberate spacing before menu navigation.
- Replaced the permanently visible ambiguous Disconnect action with one
  collapsed Session & wallet control.
- Expanded choices explain and enforce separate boundaries: Sign out ends the
  Aomi session while keeping wallets connected; Disconnect wallet tears down
  connectors while keeping the Aomi session.
- Added distinct confirmation copy for both actions and bumped the widget
  package to `@aomi-labs/widget-lib@2.0.9`.
