# 2026-09-02

- Made the root Portal wallet provider the only Para/Privy SDK owner for both
  device-auth surfaces; provider selection is URL-backed and missing or invalid
  public configuration now fails with stable, secret-safe codes.
- Fixed OAuth device authorization so the authenticated browser claims and
  displays the client, resource, and scopes before either approval or denial.
- Expanded the guarded dynamic-registration policy to the supported public MCP
  authorization-code and REST device-code clients while retaining exact
  resource and scope validation.
- Replaced process-local CLI login grants and link intents with AES-GCM sealed,
  five-minute, atomically consumed `ba_verifications` records. No schema change
  was introduced.
- Verification: all 454 Portal tests, Portal and account typechecks, Portal
  lint, formatting/diff checks, and the account 0.2.4 package dry-run passed.
  Live Para/Privy credentials and staging were not used.
- Hardened the follow-up after a skeptical acceptance review: public DCR now
  requires an explicit `token_endpoint_auth_method=none`; the pinned MCP plugin
  no longer widens every client with default resources; resource-less Codex
  registrations transactionally bind to their first exact authorize resource.
- Provider is mandatory in custom login/link records, provider mount failures
  are contained behind stable codes, post-connect errors never render raw
  details, database consumption failures keep a JSON response, and link-intent
  replacement is transactional.
- Added disposable PostgreSQL verification with separate Node processes for
  cross-instance encrypted exchange, replay races, authenticated expiry,
  rollback continuity, namespace cleanup, and concurrent resource binding.
  Added production-route Better Auth flows for Agent REST and Pipeline REST,
  each covering DCR, code issue, authenticated claim, approval, access token,
  and refresh token. All 468 normal Portal tests and 139 account tests pass;
  six database tests also pass in randomized loopback schemas that are dropped
  in failure-safe cleanup.
- Hardened `@aomi-labs/client` account and resource authorization: account-first
  provider login, explicit subject/origin-bound OAuth grants, strict token
  validation and revocation, transactional multi-resource acquisition, and
  credential-safe backend switching/logout.
- Made `account whoami` account-session-only and preserved actionable account
  API error bodies/statuses. Added focused regression coverage for scope,
  precedence, migration, subject mismatch, malformed token responses, rollback,
  remote failure, and complete local credential clearing.
- Closed the identity-deletion race by requiring and row-locking the backing
  Better Auth user inside canonical account resolution; a session captured
  before deletion can no longer recreate a carrier or canonical account.
- Scoped last-factor protection to real SIWE/SIWS wallet removal, excluding
  email carrier rows and allowing an explicit Para/Privy identity unlink.
- Made guest consent reject scopes outside the signed resource policy before
  applying the server-owned guest ceiling.
- Verified the production Better Auth foreign-key cascade in a disposable
  local PostgreSQL database: deleting one login user removed two browser
  sessions, an OAuth refresh token, its access token, consent, and an approved
  device code; explicit canonical-account cleanup removed the WST row. Account
  and Portal suites, typechecks, scoped lint, formatting, and diff checks passed.
- Added a production-route RFC 8252 loopback regression around the real Better
  Auth 1.7.1 handler. Exact and changed-port callbacks work only for the same
  IPv4 or IPv6 loopback URI; protocol, address, path, query, userinfo, fragment,
  localhost, and non-loopback variations fail. Failure diagnostics contain
  only hashes, counts, comparison booleans, package version, and deployment SHA.
- Consolidated browser API authorization across Agent and Pipeline REST, SSE,
  and chat so resource OAuth wins, account/WST follows, and guest auth is used
  only when no authenticated bearer is required. Authentication is restricted
  to the configured Aomi origin and known public route families, and a 401
  retry cannot silently change identity.
- Added managed, non-cookie CORS and OPTIONS handling for the public Agent and
  Pipeline BFF routes. Replaced the caller-controlled in-memory widget limiter
  with a shared expiring `ba_verifications` counter keyed by managed origin and
  a platform-owned client-address header; ordinary forwarded headers cannot
  reset the quota.
- Kept the widget frame stable across anonymous-to-authenticated transitions by
  delegating bearer refresh instead of key-remounting the runtime. Regression
  coverage preserves the thread, draft, and in-flight response while the next
  authenticated poll switches to the WST.
- Combined verification on the stacked head: Portal 510/510, account 158/158,
  and client 299 passed with one pre-existing contract skip. Client, React, and
  widget builds and the client/account/Portal typechecks pass. Staging,
  bottom-up merge, and npm release remain explicit later gates.
