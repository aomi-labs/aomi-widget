# Frontend Setup

Start with the package-level `AomiWidget`. It is the supported consumer
boundary for Next.js, Vite, and other React applications: one component owns
Portal transport, account state, wallet providers, chains, and transaction
execution defaults.

## Architecture

```text
consumer origin
  └─ AomiWidget (credentials included)
       └─ Portal/BFF (/api/auth, /api/aomi, /api/thread, /api/threads)
            ├─ BetterAuth + provider/SIWE verification
            ├─ canonical Aomi account
            └─ AccountBearer-authenticated backend proxy
```

The consumer does not run BetterAuth, proxy backend requests, or mint account
bearers. This keeps one session and one canonical account across Portal,
Landing, external widgets, and the CLI.

## Install and mount

```bash
npm install @aomi-labs/widget-lib
```

```tsx
"use client";

import { AomiWidget } from "@aomi-labs/widget-lib";
import { paraAuth } from "@aomi-labs/widget-lib/providers/para";
import "@aomi-labs/widget-lib/styles.css";

export default function AssistantPage() {
  return (
    <main style={{ height: "100dvh" }}>
      <AomiWidget
        apiUrl={process.env.NEXT_PUBLIC_AOMI_PORTAL_URL!}
        auth={paraAuth({
          apiKey: process.env.NEXT_PUBLIC_PARA_API_KEY,
          environment: "PROD",
          appName: "My product",
        })}
        height="100%"
      />
    </main>
  );
}
```

See the [Quickstart](/docs/build/quickstart) for Privy, providerless SIWE, Vite
shims, Portal trusted origins, and server verifier variables.

## Product configuration

Override only what differs from Aomi's defaults:

```tsx
import { base, mainnet } from "wagmi/chains";

<AomiWidget
  apiUrl={process.env.NEXT_PUBLIC_AOMI_PORTAL_URL!}
  auth={paraAuth({ apiKey: process.env.NEXT_PUBLIC_PARA_API_KEY })}
  wallets={{
    evm: {
      chains: [mainnet, base],
      wallets: ["metamask", "rabby", "coinbase"],
      walletConnectProjectId: process.env.NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID,
    },
    solana: false,
  }}
  controlBarProps={{ hideApiKey: true, hideNetwork: false }}
  persistThread
/>;
```

The package stylesheet is already compiled. Host apps may wrap the widget and
use `className` or `style`, but do not need to scan package source with
Tailwind.

## Custom layouts

For a layout that intentionally owns provider composition, use
`AomiWalletKitProvider` with the `AomiFrame` compound API. Keep the same Portal
URL and credentialed client policy:

```tsx
import { AomiFrame, AomiWalletKitProvider } from "@aomi-labs/widget-lib";

<AomiWalletKitProvider
  auth={false}
  account={{ mode: "aomi-backend", baseUrl: portalUrl }}
>
  <AomiFrame.Root
    backendUrl={portalUrl}
    clientOptions={{ credentials: "include" }}
    height="100%"
  >
    <AomiFrame.Header />
    <AomiFrame.Composer withControl />
  </AomiFrame.Root>
</AomiWalletKitProvider>;
```

Prefer `AomiWidget` unless you need to replace the compound layout or provider
tree; the lower-level API makes the host responsible for keeping account and
transport URLs aligned.

## Release checklist

- The consumer imports `styles.css` once.
- `apiUrl` points to Portal, not the raw backend.
- Portal trusts every production and preview consumer origin.
- Para/Privy public identifiers match Portal verifier configuration.
- Server secrets are absent from browser environment variables and bundles.
- Anonymous chat, provider or SIWE login, refresh persistence, and a wallet
  signing prompt have been tested on the deployed origin.
