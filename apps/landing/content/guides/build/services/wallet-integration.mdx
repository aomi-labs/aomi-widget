# Wallet Integration

`AomiWidget` owns the default Para/Privy, wagmi, Solana, account, and runtime
provider trees. Mount one component and select embedded auth with a helper, or
omit `auth` for external-wallet/SIWE mode.

## Install

```bash
npm install @aomi-labs/widget-lib
```

Import `@aomi-labs/widget-lib/styles.css` once. The CSS is precompiled and does
not require Tailwind source scanning.

## Provider modes

### Para

```tsx
import { AomiWidget } from "@aomi-labs/widget-lib";
import { paraAuth } from "@aomi-labs/widget-lib/providers/para";
import "@aomi-labs/widget-lib/styles.css";

<AomiWidget
  apiUrl="https://chat.aomi.dev"
  auth={paraAuth({
    apiKey: process.env.NEXT_PUBLIC_PARA_API_KEY,
    environment: "PROD",
  })}
/>;
```

### Privy

```tsx
import { AomiWidget } from "@aomi-labs/widget-lib";
import { privyAuth } from "@aomi-labs/widget-lib/providers/privy";

<AomiWidget
  apiUrl="https://chat.aomi.dev"
  auth={privyAuth({ appId: process.env.NEXT_PUBLIC_PRIVY_APP_ID })}
/>;
```

### External wallet / SIWE

```tsx
import { AomiWidget } from "@aomi-labs/widget-lib";

<AomiWidget apiUrl="https://chat.aomi.dev" />;
```

Providerless mode does not import a Para or Privy helper. It exposes configured
external wallets, and an EVM wallet can prove ownership through Portal SIWE.
No private key leaves the wallet.

## Auth and account flow

Provider auth and wallet signing are separate responsibilities:

1. Para/Privy authenticates the user and exposes provider-attested wallets, or
   an external EVM wallet signs a SIWE challenge.
2. The widget sends the provider credential or SIWE proof to Portal.
3. Portal verifies it and resolves the canonical Aomi account.
4. Portal mints short-lived AccountBearers server-side when proxying protected
   backend traffic.
5. Transaction signing still happens in the selected browser wallet.

The browser never receives Portal signing keys, provider verifier secrets, or
backend account-bearer signing material.

For cross-origin widgets, Portal must trust the consumer origin through
`AOMI_TRUSTED_ORIGINS`. Prefer exact origins; narrow `*` patterns are supported
for changing preview hosts. The provider public key/app id used in the browser
must match Portal's Para/Privy verifier configuration.

## Chains and wallets

Ethereum, Arbitrum, Optimism, Base, Polygon, Sepolia, Linea, and Monad are
available by default, alongside Solana mainnet, devnet, and testnet. Override
the catalog only when the product needs a narrower set:

```tsx
import { arbitrum, base, mainnet, optimism, polygon } from "wagmi/chains";

<AomiWidget
  apiUrl="https://chat.aomi.dev"
  wallets={{
    evm: {
      chains: [mainnet, polygon, arbitrum, base, optimism],
      wallets: ["metamask", "rabby", "coinbase", "baseAccount"],
      walletConnectProjectId: process.env.NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID,
    },
    solana: false,
  }}
/>;
```

Use `walletFamilies={["evm"]}` to narrow the visible controls, or set
`wallets.evm` / `wallets.solana` to `false` to disable a runtime entirely.

## Transaction signing flow

When the assistant determines that a transaction is needed:

```text
assistant tool call
  → backend wallet request event
  → widget review/approval UI
  → local wallet signature
  → transaction result returned to backend
  → assistant continues with the result
```

`AomiWidget` includes the runtime transaction handler. The host app does not
need to subscribe to wallet events for the default flow.

## Account abstraction

The widget defaults to optional account abstraction with an external-wallet
owner and native-wallet fallback. Customize it through `execution`:

```tsx
<AomiWidget
  apiUrl="https://chat.aomi.dev"
  execution={{
    aa: "optional",
    provider: "alchemy",
    modes: ["4337"],
    owner: "external-wallet",
    sponsorship: {
      mode: "optional",
      paymasterServiceUrl: "/api/paymaster",
    },
  }}
/>
```

Keep paymaster and provider secrets behind a server endpoint. Only public
provider identifiers belong in browser environment variables.

## Headless signing

Applications using `@aomi-labs/react` without the widget can handle requests
manually:

```tsx
import { useAomiRuntime, useWalletHandler } from "@aomi-labs/react";
import { useSendTransaction } from "wagmi";

function WalletRequestHandler() {
  const { currentThreadId } = useAomiRuntime();
  const { pendingRequests, startProcessing, resolveRequest, rejectRequest } =
    useWalletHandler({ sessionId: currentThreadId });
  const { sendTransactionAsync } = useSendTransaction();

  async function approve(request: (typeof pendingRequests)[number]) {
    startProcessing(request.id);
    try {
      if (request.kind !== "transaction") return;
      const payload = request.payload as {
        to: `0x${string}`;
        value?: string;
        data?: `0x${string}`;
      };
      const txHash = await sendTransactionAsync({
        to: payload.to,
        value: BigInt(payload.value ?? "0"),
        data: payload.data,
      });
      resolveRequest(request.id, { txHash });
    } catch (error) {
      rejectRequest(
        request.id,
        error instanceof Error ? error.message : "Wallet request failed",
      );
    }
  }

  return pendingRequests.map((request) => (
    <button key={request.id} onClick={() => void approve(request)}>
      Review transaction
    </button>
  ));
}
```

The headless path also makes the host responsible for provider composition,
account auth, and credentialed Portal transport. Prefer `AomiWidget` unless a
custom UI requires that control.
