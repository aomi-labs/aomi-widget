# Configuration

`AomiWidget` is the complete consumer component. Its required `apiUrl` is the
Portal/BFF origin used for BetterAuth, accounts, threads, chat, polling, and
SSE. It must not point at the raw backend when browser account auth is enabled.

## Minimal configuration

```tsx
import { AomiWidget } from "@aomi-labs/widget-lib";
import "@aomi-labs/widget-lib/styles.css";

<AomiWidget apiUrl="https://chat.aomi.dev" />;
```

This is providerless mode. External wallets remain available and EVM wallets
can authenticate through Portal SIWE. The widget sends credentials on every
Portal transport and aligns its account runtime with the same URL.

## Auth providers

Provider choice changes only the helper passed to `auth`.

### Para

```tsx
import { paraAuth } from "@aomi-labs/widget-lib/providers/para";

<AomiWidget
  apiUrl={portalUrl}
  auth={paraAuth({
    apiKey: process.env.NEXT_PUBLIC_PARA_API_KEY,
    environment: "PROD", // "BETA" by default
    methods: ["email", "google"],
    appName: "My product",
    appDescription: "On-chain assistant",
    appUrl: "https://app.example.com",
  })}
/>;
```

### Privy

```tsx
import { privyAuth } from "@aomi-labs/widget-lib/providers/privy";

<AomiWidget
  apiUrl={portalUrl}
  auth={privyAuth({
    appId: process.env.NEXT_PUBLIC_PRIVY_APP_ID,
    methods: ["email", "google", "wallet"],
    appName: "My product",
    appLogoUrl: "https://app.example.com/logo.png",
  })}
/>;
```

`paraAuth()` and `privyAuth()` trim their public identifier. A missing or empty
identifier returns `false`, so optional local provider configuration falls back
to providerless mode. Import only the provider helper you use; its SDK stays
out of the other widget bundle.

## Widget props

| Prop                     | Type                                 | Default                          | Purpose                                           |
| ------------------------ | ------------------------------------ | -------------------------------- | ------------------------------------------------- |
| `apiUrl`                 | `string`                             | required                         | Portal/BFF origin for account and runtime traffic |
| `auth`                   | `AomiWidgetAuthConfig`               | providerless                     | `paraAuth(...)`, `privyAuth(...)`, or `false`     |
| `width`                  | CSS width                            | `"100%"`                         | Frame width                                       |
| `height`                 | CSS height                           | `"80vh"`                         | Frame height                                      |
| `className` / `style`    | React styling                        | --                               | Host container styling                            |
| `walletPosition`         | `"header" \| "footer" \| null`       | `"footer"`                       | Sidebar wallet control placement                  |
| `walletFamilies`         | `("evm" \| "solana")[]`              | both                             | Wallet families shown in controls                 |
| `showSidebar`            | `boolean`                            | `true`                           | Thread sidebar visibility                         |
| `showHeader`             | `boolean`                            | `true`                           | Header visibility                                 |
| `controlBarProps`        | control props                        | --                               | Model, app, network, key, and wallet visibility   |
| `clientOptions`          | `Omit<AomiClientOptions, "baseUrl">` | credentials included             | Advanced transport options                        |
| `persistThread`          | `boolean`                            | runtime default                  | Restore the selected materialized thread          |
| `threadPersistenceKey`   | `string`                             | derived                          | Explicit storage key                              |
| `threadPersistenceScope` | `string \| null`                     | --                               | Tenant/user scope for the derived key             |
| `providers`              | `ProvidersConfig`                    | --                               | Low-level provider overrides                      |
| `wallets`                | `WalletsConfig`                      | built-in catalogs                | EVM/Solana wallet and network overrides           |
| `execution`              | `ExecutionConfig`                    | optional AA, auto provider, 4337 | Signing and sponsorship policy                    |
| `account`                | `AccountConfig`                      | Portal account mode              | Advanced account override or disable              |

`clientOptions.credentials` defaults to `"include"`. Override it only for a
deployment that intentionally does not use Portal cookies.

## Wallets and networks

```tsx
import { base, mainnet } from "wagmi/chains";

<AomiWidget
  apiUrl={portalUrl}
  wallets={{
    evm: {
      chains: [mainnet, base],
      wallets: ["metamask", "rabby", "coinbase", "baseAccount"],
      walletConnectProjectId: process.env.NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID,
      appName: "My product",
    },
    solana: false,
  }}
/>;
```

By default the widget supplies Ethereum, Arbitrum, Optimism, Base, Polygon,
Sepolia, Linea, and Monad EVM networks plus Solana mainnet, devnet, and testnet.
Set a family to `false` to remove it.

## Account abstraction and sponsorship

```tsx
<AomiWidget
  apiUrl={portalUrl}
  execution={{
    aa: "optional",
    provider: "pimlico",
    modes: ["4337"],
    owner: "external-wallet",
    sponsorship: {
      mode: "optional",
      paymasterServiceUrl: "/api/paymaster",
    },
  }}
/>
```

Use `aa: "required"` or sponsorship `mode: "required"` only when the selected
chains and provider configuration guarantee that capability. Optional mode
falls back to native wallet execution.

## Controls and layout

```tsx
<AomiWidget
  apiUrl={portalUrl}
  showSidebar={false}
  walletPosition={null}
  controlBarProps={{
    hideModel: false,
    hideApp: false,
    hideApiKey: true,
    hideWallet: false,
    hideNetwork: false,
  }}
/>
```

Use [`AomiFrame`](/docs/build/ui/widget/aomi-frame) with
`AomiWalletKitProvider` only when you need to replace the compound layout or
provider composition. In that advanced path, set the account `baseUrl`, frame
`backendUrl`, and client credentials consistently; `AomiWidget` normally does
that wiring for you.

## Cross-origin deployment

Portal and BetterAuth share one exact trusted-origin policy. Add every consumer
origin to the Portal server, including preview origins that need auth:

```bash
AOMI_TRUSTED_ORIGINS=https://app.aomi.dev,https://preview-*.aomi.dev
```

Origins include scheme, host, and optional port, with no path. Portal returns
credentialed CORS headers only to trusted origins. Prefer exact origins and use
`*` only for narrowly scoped preview-host patterns. Aomi's first-party
`landing-page-*-aomi-labs.vercel.app` previews are trusted automatically. The
consumer should not add its own `/api/auth/*`, `/api/aomi/*`, or backend
catch-all proxy.

Direct credentialed requests assume Portal and the consumer are same-site (for
example `chat.example.com` and `app.example.com`). On an unrelated top-level
domain, use a customer-domain Portal or a transparent same-site reverse proxy
and set `apiUrl` to that same-site origin. Trusted CORS does not bypass
SameSite or browser third-party-cookie blocking.

Para/Privy browser identifiers are public, but Portal verification keys and
provider REST secrets are server-only. See the [Quickstart](/docs/build/quickstart)
for the matching environment variables.

## Portal routes used by the widget

| Route                                        | Purpose                                   |
| -------------------------------------------- | ----------------------------------------- |
| `/api/auth/*`                                | BetterAuth sessions and SIWE              |
| `/api/aomi/account`                          | Canonical account and linked wallet graph |
| `/api/aomi/provider/exchange`                | Verified Para/Privy session exchange      |
| `/api/threads` and `/api/threads/:id`        | Thread list and lifecycle                 |
| `/api/thread/chat`                           | Submit a message                          |
| `/api/thread/state`                          | Poll thread state                         |
| `/api/thread/updates`                        | Native SSE updates                        |
| `/api/thread/models` and `/api/thread/model` | Model list and selection                  |
| `/api/thread/apps`                           | Available Aomi Apps                       |

All browser routes above go through Portal. Portal decides whether to forward
an anonymous request or mint an AccountBearer for an authenticated canonical
user.
