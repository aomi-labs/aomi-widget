# `@aomi-labs/deploy` — implementation plan

> Branch: `deployment-client` (worktree off `aomi-widget` `origin/main`)
> Spec sources: ADR 0011 (internal `aomi-launch-my-agent/ralph/adr/0011-krexa-deploy-proxy.md`
> + partner `krexa-hosted-apps:publish/docs/adr/0011-fe-deploy-proxy.md`),
> ADR 0004 (`aomi-git` contract), ADR 0009 (DB-driven platforms + `deployment.json`).

## Goal

A **server-side, Node-only** TypeScript client to the Aomi deployment platform —
the privileged engine of the ADR 0011 deploy-proxy. It performs the two
credentialed operations a browser cannot:

1. **deploy** — commit `apps/<slug>/` to `publish` via the GitHub Git Data API
   (reproducing the `aomi-git deploy` contract, no git binary).
2. **activate** — call the Aomi backend `POST /api/admin/apps/activate` with the
   platform-wide activation token + transient read PAT.

Plus **status** polling to bridge the CI gap.

## Explicitly NOT in this package

- Per-user/session → slug ownership resolution (depends on consumer's records).
- Audit logging storage (we expose an `onAudit` hook; consumer persists).
- Browser code / any secret in a bundle. **Node-only.**
- Auto-activate at push (impossible to express by design — separate methods).

## Boundaries baked in (the security crux)

- **Server-only guard:** `index.ts` throws on import if `typeof window !== "undefined"`.
- **Staged-path guard:** `deploy()` rejects any source path outside `apps/<slug>/`.
- **Narrow-only tags:** `activate()` asserts `target_tags ⊆ deployment.json server_tags`.
- **Deploy ≠ activate:** two methods; no combined call → no CI-race 502.
- Secrets (`botPat`, `activationToken`) are constructor inputs, never hardcoded
  or read from a fixed env name inside the lib.

## Public API (draft)

```ts
const dc = new DeploymentClient({
  github: { repo: "aomi-labs/krexa-hosted-apps", branch: "publish", botPat: "..." },
  aomi:   { backendUrl: "https://api...", platform: "krexa", activationToken: "..." },
  onAudit?: (e: AuditEvent) => void,   // consumer persists; lib calls on every op
});

// 1. deploy — commit apps/<slug>/ to publish, return the (future) release tag
const { releaseTag, commitSha, ciUrl } = await dc.deploy({
  slug, displayName, files /* SourceBundle: path→content under apps/<slug>/ */,
  serverTags: ["staging"], isPublic: false,
});

// 2. status — poll until release ready (consumer drives the loop / progress UI)
const { ci, release, releaseTag } = await dc.getStatus(slug);

// 3. activate — only after release ready; narrow-only target tags
await dc.activate({ slug, targetEnv: "staging" /* ⊆ serverTags */ });
```

`SourceBundle` keys are repo-relative paths; `deploy()` **prepends/validates
`apps/<slug>/`** and refuses anything else. `deployment.json` is generated by the
lib (not taken from the caller) so the contract can't be forged.

## `deployment.json` contract (generated, ADR 0004/0009)

```jsonc
{
  "app":    { "name", "display_name", "platform": "krexa",
              "git": "https://github.com/aomi-labs/krexa-hosted-apps",
              "public": false, "server_tags": ["staging"] },
  "target": { "branch": "publish", "app_path": "apps/<slug>",
              "release_tag": "apps-<slug>-<short-commit>", "server_tags": ["staging"] }
}
```
Written to `apps/<slug>/.aomi/deployment.json`. `contract-drift.test.ts` fixture-
diffs this against real `aomi-git deploy` output to catch ADR-0004 drift.

## Activate body (verified against backend `ActivateAppRequest` on main)

`{ app_slug, platform, source_repo, app_release_tag, source_commit, is_public,
   target_tags, github_token }` — Bearer = activation token; `github_token` =
transient read PAT (one-shot fetch, never persisted by backend).

## Build steps (in order)

1. Scaffold `packages/deploy` (package.json, tsup, tsconfig) mirroring `packages/client`.
2. `types.ts` + `errors.ts` + `contract.ts` (ActivateAppRequest mirror).
3. `release-tag.ts` + `deployment-json.ts` + unit tests.
4. `github.ts` — Octokit Git Data commit (blobs→tree→commit→update `publish` ref)
   + staged-path guard.
5. `client.ts` — wire deploy/getStatus/activate + `onAudit` + narrow-only assert.
6. `index.ts` + window guard; export public surface.
7. `contract-drift.test.ts` against an `aomi-git deploy` fixture.
8. Wire into pnpm workspace build; `pnpm --filter @aomi-labs/deploy build` + `vitest`.
9. README: server-only usage, the ownership/audit responsibilities left to consumer.
